# Standalone web-repl extraction, shell, and notebook persistence

**Area:** `web-repl` · **Converged:** True · **Rounds:** 1 · **Adjudicated verdict:** REVISE

## Summary

Extract the PyLabRobot JupyterLite payload out of the Angular SPA into a new top-level `web-repl/` whose deployed artifact is the stock JupyterLite `lab/` surface served as the TOP-LEVEL document (design B′ INJECT, brainstorm session 0abdd344). No Angular, no iframe, no framework. One dependency-free `web-repl/shell/praxis-shell.js` is injected into the generated `lab/index.html` by an asserting post-build step; it exists for exactly one reason — to be main-thread JS that can call `requestDevice()` inside a live user-activation window, preserving the commit-97a75988 gesture chain. The kernel↔shell protocol stays BroadcastChannel `'praxis_repl'` verbatim (message shapes are the contract, not a JS API), which is what makes a later labextension rewrite reachable without touching Python.

Five things change materially: (1) a real, CI-enforced, fail-loud build replaces the dead hand-committed tree; (2) Pyodide is vendored so the site stops hard-depending on cdn.jsdelivr.net; (3) the wheel filename comes from a generated `manifest.json` instead of three hardcoded literals, and `praxis:ready` is emitted only after `import pylabrobot` succeeds; (4) `contentsStorageName`/`settingsStorageName` are pinned to fixed literals IN THE SAME COMMIT that moves the served path, with a one-time copy from the legacy `JupyterLite Storage - ${baseUrl}` database; (5) persistence becomes four real layers (IndexedDB → `navigator.storage.persist()` → File System Access working folder → `.ipynb` export/import), with the current tier displayed permanently.

Direct Control and the protocol-runner worker retire to the deferred experimental extension. Two one-liners land first and are independently valuable: drop `window` from `web_serial_shim.py`'s `js` import (WebSerial has NEVER worked in the JupyterLite kernel), and delete the unconditional `PyodidePoolService.preWarm()` at `praxis/web-client/src/main.ts:22-31`.

ONE GATE BLOCKS THE CRITICAL PATH: no spike in any architecture has ever exercised the `requestDevice()` gesture chain against real hardware. W3 (`praxis-shell.js`) MUST NOT start until spike S0 runs on a real machine with a real device. Design A (thin vanilla host + iframe) is the named fallback and this decision reopens without embarrassment if S0 shows cross-frame delegation is more reliable.

## The kernel↔shell contract (VERBATIM — this is the seam, do not redesign it)

BroadcastChannel name: **`'praxis_repl'`** (`praxis_bootstrap.py:90`; `web_bridge.register_broadcast_channel` at `web_bridge.py:924` stores it in `_broadcast_channel`).

| direction | shape | source |
|---|---|---|
| kernel → shell | `{type:'praxis:ready'}` | `praxis_bootstrap.py:288-290` |
| kernel → shell | `{type:'USER_INTERACTION', payload:{id, interaction_type, payload:{api, filters}}}` | `web_bridge.py:1105-1107` |
| shell → kernel | `{type:'praxis:interaction_response', id, value}` | consumed at `praxis_bootstrap.py:151-158` → `web_bridge.handle_interaction_response` (`web_bridge.py:1131`) |
| shell → kernel | `{type:'praxis:execute', code, label}` | `praxis_bootstrap.py:110` |

NEW messages this spec adds (kernel→shell `praxis:shell-ping`, shell→kernel `praxis:shell-pong`, kernel→shell `praxis:error`). Nothing existing is renamed.

**Gesture chain to preserve (commit 97a75988).** Today: `web_bridge.request_user_interaction()` (worker) → BroadcastChannel → `playground-jupyterlite.service.ts:127-129` → `playground.component.ts:476-490` `handleUserInteraction()` → `InteractionService` → `interaction-dialog.component.ts:97-121` `connectDevice()` — where `navigator.usb.requestDevice({filters})` (:105) / `navigator.serial.requestPort` (:107) / `navigator.hid.requestDevice` (:109) are called **directly from the `(click)` handler with no intervening `await`** so transient activation survives. `praxis-shell.js` is a line-for-line reimplementation of `connectDevice()` in a native `<dialog>`. THE INVARIANT: **zero `await` between the click event and the `requestDevice()` call.** Any refactor that awaits first (to fetch filters, to log, to check permissions) silently breaks the product's core requirement and will not be caught by a code review that only reads for correctness.

## Design decisions carried from session 0abdd344 with implementation deltas

**Shell presence must be proven ACROSS REALMS, not by a global.** The brainstorm's mitigation ("`praxis-shell.js` sets a global sentinel on load; the bootstrap refuses `praxis:ready` without it") is not directly realizable: the bootstrap runs in a `DedicatedWorkerGlobalScope` and cannot read a `window` global. Realizable equivalent, and what this spec requires: the shell broadcasts `{type:'praxis:shell-pong'}` in reply to `{type:'praxis:shell-ping'}`; the bootstrap pings every 250 ms for up to 5 s before step 11 and emits `{type:'praxis:error', reason:'shell-missing'}` instead of `praxis:ready` if no pong arrives. Same guarantee, correct realm.

**Storage identity — ordering IS the decision.** Pin `contentsStorageName: "praxis-repl-contents"`, `settingsStorageName: "praxis-repl-settings"`, AND `workspacesStorageName: "praxis-repl-workspaces"` in the SAME commit that changes the served path. **G2 amendment (260817):** the three-key requirement is confirmed, not merely proposed — GATE G2 spike S-C found `LiteWorkspaceManager.activate` reads `workspacesStorageName` independently (`a=getOption("workspacesStorageName")||i`) of `contentsStorageName`/`settingsStorageName`, and pinning only the first two left two orphaned per-baseUrl `JupyterLite Storage - ${baseUrl}` workspace databases behind (`store_enumeration_clean=false`). All three together produced `store_enumeration_clean=true` — see `.praxia/docs/research/260817_g2-spike-battery-verdict.md` criterion G2-4. Ship the move first and every existing notebook is orphaned: data on disk, invisible to the app, no in-app recovery.

**Loud readiness generalizes to three failure modes**, all of which currently pass silently: (1) wheel 404 → observed `praxis:ready` fired anyway with `pylabrobot` absent; (2) shell missing; (3) `_sync_fetch` returning `None` on a 0-byte 200, logging a false `fetch failed` on every boot and training operators to ignore the exact channel a real missing shim would use.

**One patch implementation.** `praxis/web-client/src/assets/shims/pyodide_io_patch.py` is dead on the JupyterLite path (never fetched) yet its docstring claims it is auto-executed, and it produces module-level shim classes where the bootstrap produces `builtins`-exec'd ones — two distinct `WebSerial` classes can coexist. It is NOT moved into `web-repl/`; it retires with the deferred surfaces.

**`_mock_native_deps` ordering.** `'serial'` is MagicMocked at `praxis_bootstrap.py:44-48` before any shim injection, and `pyodide_io_patch._inject_serial_shim` is guarded by `if "serial" not in sys.modules` — so `import serial; serial.Serial` is a MagicMock forever (observed `global_serial_shim=False` vs `global_usb_shim=True`). Fix: inject shims into `sys.modules` BEFORE `_mock_native_deps()`, and have `_mock_native_deps` skip any name already present.

**Angular keeps a PINNED embed (F2, "kept alive" made observable).** `praxis/web-client/angular.json` gains an asset entry copying a pinned `web-repl` release tarball into `dist/.../assets/repl/`; the playground iframe points at that same-origin path. Angular then breaks at an explicit version bump, not continuously. This is the honest deferral, not maintenance.

## What this spec deliberately does NOT do

- Does not bump PLR to 0.2.2 or migrate `pylabrobot.liquid_handling` → modern top-level vendor packages. `build_wheels.py` builds whatever `external/pylabrobot` is pinned to and records the resulting filename in `manifest.json`. The version bump is a separate area with its own spec; this spec removes the filename hardcoding that makes the bump dangerous. `debt-1291` is untouched here.
- Does not add COOP/COEP. The standalone spike observed `crossOriginIsolated=False` with the kernel booting fine. Do not make it a requirement.
- Does not stack a second service worker. JupyterLite ships one; a second is the worst debugging class in web dev and is unnecessary once Pyodide is vendored same-origin.
- Does not put "PWA implies persistent storage" on the critical path — undocumented Chromium heuristic, not a spec guarantee.
- Does not add the visualizer. Separate area.

## Risks

- THE GESTURE CHAIN IS UNPROVEN IN EVERY ARCHITECTURE, INCLUDING THE INCUMBENT. No spike attached a device or called requestDevice(). B′ changes the realm topology under a mechanism nobody re-verified, which is uncomfortable and is recorded as such in the brainstorm's own steelman for A. The counter-argument 'serial is broken anyway' is true for WebSerial but NOT for WebUSB/WebHID, whose shims were observed healthy (IN_PYODIDE=True) — so for two of three transports, Design A really is defending a plausibly-working incumbent. G0 is the mitigation; if it fails, A wins.
- PATCHING A GENERATED FILE IS B′'S STRUCTURAL WEAKNESS. inject_shell.py edits lab/index.html, which jupyterlite regenerates. Stability across JupyterLite versions is UNTESTED and the project is simultaneously moving 0.7.1 -> 0.8.1. Mitigated in two independent layers (build-time anchor assertion on 'id="jupyter-lite-main"', runtime ping/pong handshake) but not eliminated. Design A never patches a generated file, so a JupyterLite bump cannot unshell it.
- THE STORAGE-NAME PIN IS ONLY READ-VERIFIED. Everything about the path move rests on `PageConfig.getOption("contentsStorageName")||default` observed in minified 0.8.1 source. If it does not behave as read, T08's migration is built on sand and the path move becomes the data-loss event it was designed to prevent. G3 exists solely to close this before anything depends on it.
- VERSION SKEW BETWEEN WHAT WAS TESTED AND WHAT SHIPS. All persistence findings are verified on jupyterlite-core 0.8.1 / pyodide-kernel 0.8.2; the deployed husk reports appVersion 0.7.1; pyproject pins only >=0.7.1 / >=0.7.0. The localforage/BrowserStorageDrive design is long-standing but the 0.7.1 line was never directly verified. R4's exact pin is the mitigation — an unpinned floor means the artifact tested in CI and the artifact a developer builds can differ silently.
- PLAYWRIGHT IS EFFECTIVELY UNRUNNABLE ON THIS DEVELOPMENT BOX. Chromium cannot launch under the Bash sandbox (apply-seccomp: unshare(CLONE_NEWUSER): Invalid argument); playwright 1.62.0 wants chromium build 1234 which cannot be downloaded (its CDN is not allowlisted); bun cannot install packages ('unable to write files to tempdir: ReadOnlyFileSystem'). Every browser gate will be run in CI or with dangerouslyDisableSandbox plus an explicit executable_path. Any plan that assumes a developer casually reruns the e2e suite locally is wrong.
- A VACUOUS TEST IS WORSE THAN NO TEST, AND THREE SPECIFIC ONES ARE EASY TO WRITE HERE: page.route() misses Web Worker requests (offline gate passes while the CDN is still reachable); a dispatched synthetic click carries no user activation (gesture gate passes while proving the opposite); comparing filenames instead of content shows storage isolation is gone when it is not (this false positive actually happened in spike1d and was only caught by spike1e). All three are called out in T14 and the gates, but they will recur under time pressure.
- VENDORED PYODIDE GETS 'TEMPORARILY' REVERTED TO THE CDN when the artifact size or the fetch step becomes annoying. The pre-mortem named this explicitly. The only durable defence is the CI offline gate — if that gate is ever made non-blocking, the reversion follows within a release.
- 'KEPT ALIVE' (F2) DECAYS BY NEGLECT. Moving Direct Control and the protocol runner to src/app/experimental/ without a build that compiles them means they rot into non-compiling code and get deleted 'because they were already broken'. T22/T24's verification includes `bun run build` exiting 0, but nothing verifies the experimental code still RUNS. Accept this consciously or add a compile-only job.
- THE PLR 0.2.2 BUMP IS DELIBERATELY OUT OF SCOPE AND SOMEONE WILL DO IT ANYWAY MID-STREAM. This spec makes the bump safe (manifest indirection, loud failure, one patch site) but does not perform it. Sequencing the bump before T04+T06 land reintroduces exactly the silent 404 failure mode this spec removes. debt-1291 stays open on purpose.
- THE FIRST-SAVE MODAL IS A UX TAX ON EVERY NEW USER and there will be pressure to soften it to a banner. That softening is precisely the pre-mortem's #1 failure narrative — 'savable becomes a lie again'. If it is softened, the tier indicator's permanence and alarm level become the last line of defence and must not be softened with it.
